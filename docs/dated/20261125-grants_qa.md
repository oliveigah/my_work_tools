# Grants redesign QA: review of 2026-11-25

A QA pass on the grants redesign (`14d3c01`, `2404837` on `main`):
whether the code does what [grant_mental_model.md](../grant_mental_model.md)
settled, whether its guarantees hold, and whether what humans and agents
read about it is coherent. The probes behind each finding are in
`test/review/qa_20261125/` (named `*_probe.exs`, so the suite leaves them
out); run one with `mix test test/review/qa_20261125/<area>/<file>`. A
failing probe is a guarantee that doesn't hold.

The main operation it was read against: an agent in the VM works for you;
whatever it does that leaves the VM goes through MWT, under grants you
set, over resources you can lock; you see what it did and how each action
was decided; a credential's real value never reaches anything the agent
wrote.

## Summary

The model holds where it is simplest. Off gives nothing; a use needs an
on grant over every resource; the most permissive grant counts within a
resource and a refusal beats an ask beats a yes across them; locks,
blocked hosts, *Except these hosts* and isolation refuse fixed calls as
they refuse the agent's own requests; a fixed request covers only its
credential in its own request, goes through the proxy with a mark the VM
can't forge, and never gets further than the agent's own request would
(27 network settings tried). Commands agents write always ask, whatever
lever is pulled. Values can't change a fixed request's host, headers or
body shape, nor what a saved command runs. Proposals carry nothing of
yours. MWT's tools grants hold.

What doesn't hold gathers where a **reader that guesses is used to
decide**, and where **an answer comes back**:

1. **Pins (Q10) miss most of what they promise.** The file reader is the
   hints' reader, written "for hints, not for deciding", and a saved
   command accepted from a proposal is never pinned at all.
2. **"Allow similar, any id" lets `*` stand for `..`,** so an allowance
   on one webhook's DELETE sends GitHub's real value to `…/hooks/..`.
3. **Answers are only scanned for the value put into that request,** so
   another of your values in an answer reaches the VM. This predates the
   redesign; the model's point 13 claims more.
4. **The grade (Q8) reads a pattern as narrow, whatever it lets through,**
   and misses common shapes of Open. Q8 makes the grade the only warning
   before *Auto*, so a false *Narrow* is the dangerous direction.

The suite is green (146 doctests, 2365 tests). Probes: host commands 59
(26 fail), network 44 (10 fail).

## Fixed after the review

Every finding below but 7 (withdrawn) is fixed, and every probe passes
(103). The suite is green (158 doctests, 2407 tests). By finding:

1. **Pins.** One reader of what a script runs,
   `MWTClient.Sandbox.ScriptRuns`, behind pins, the card's hints and the
   grade: quotes, wrappers with their own options, interpreters' real
   flags, `source`, stdin forms, `cd` followed. A file it can't tell
   (a variable in the command or path, `cd -`, code piped in) is a pin
   with no path, and each run of a saved command holding one asks. A
   saved command is pinned as you accept it; one never pinned (saved
   before pins, imported) asks once, showing its file.
2. **`*` and dot segments.** A `*` no longer stands for `.`, `..`, an
   empty segment or their encoded forms, and a request carrying a
   credential whose path has a dot segment or a backslash is refused
   (`mwt_bad_request`): MWT reads attributes and allowances on the path
   as sent, and a host normalising it would act on another.
3. **Answers.** Every answer MWT reads is looked through for all your
   values, over HTTP/1.1, HTTP/2 and WebSockets; one found is cut and the
   firewall told, as an echo was. Costs: about 37% of a large download's
   throughput (≈650 → ≈400 MB/s on this machine, 64 MiB); MWT asks only
   for encodings it decodes (gzip, deflate); and while it holds values, an
   answer it can't read (a head over 64 KiB, broken framing, `br` sent
   anyway) is refused or cut rather than passed on. Still unscanned: hosts
   set to *Don't read*, a protocol other than HTTP inside TLS MWT ended,
   a value split across WebSocket frames.
4. **The grade** (still a warning, Q8 as you chose): a pattern proves
   *Narrow* only when, anchored at both ends, it excludes whitespace,
   shell characters, `/`, `..` and a leading `-`; *Open* covers every
   form found, behind wrappers too. Over-grading is deliberate.
5. **Names** the VM chose (parameters, `--set`, `--fill`) are scanned like
   values.
6. **Refused asks** (a call or a command refused before anything ran)
   leave a line, decided by MWT.
8. **A call's card** names every grant that asked (*Also asking*), and
   *Allow for a while* can go on each. An allowance made for the agent's
   own request still doesn't cover a call (its network is asked about the
   call): stricter, kept, and said in the model.
9. **Smaller gaps:** encoded placeholders are found; a credential only
   fixed calls are over has its placeholder checked like any other; the
   floor treats `\` as a separator and decodes `%xx`; names programs read
   from the environment (`PYTHONPATH`, `*_PROXY`…) are refused as
   parameters; a fixed call's DNS answer is no longer kept for the VM.

What the reader still can't tell: what a file runs in turn (make, npm
run), functions and aliases the shell already has, files an interpreter's
inline code opens, `X=$P; $X` for the grade (pins treat it as unknown).

## Findings, most important first

### 1. Pins don't hold for the forms that matter (important, new)

- **An accepted proposal is never pinned.** Only adding or editing a
  grant on its page pins (`server.ex:1032`, `:1062`); accepting on the
  review page (`Grants.review`) doesn't, and a run of a grant with no
  pins counts as unchanged (`host_runs.ex:689`). You accept an agent's
  `./deploy.sh` saved command with *Auto*; the file changes; its first
  run goes unasked. Every saved command made before this release is in
  the same state. A proposal whose `--dir` is the workspace's `from-vm`
  would run a file the agent wrote, unasked (read in the code, not
  probed). Probe: `commands/proposals_probe.exs`, "an accepted saved
  command keeps its file as it was when you accepted it".
- **The reader misses common forms.** `HostCommand.commands/1` keeps only
  a path's basename (`host_command.ex:387`), so `scripts/deploy.sh` and
  absolute paths aren't pinned; `cd sub && ./x.sh` pins the folder's own
  `x.sh` and runs `sub/x.sh` unpinned (`pins.ex:113`); quotes, `timeout`,
  `nice -n`, `bash --norc`, `python3 -W ignore`, `bash < x` and
  `cat x | sh` aren't seen. End to end, a saved command on *Auto* ran a
  changed `scripts/deploy.sh` and a changed `sub/x.sh` unasked. Probes:
  `commands/pins_evasion_probe.exs`.
- **Why:** the reader's own doc says "Quotes are not parsed: this is for
  hints, not for deciding"; pins made it decide. One block, two meanings.
- **Fix:** pin at review, and treat a saved command with no pins as
  changed (each old one asks once). Give pins a reader of their own that
  keeps paths, follows `cd`, and when it can't tell what runs, says so on
  the card and asks, rather than pinning nothing.

### 2. *Allow similar, any id* covers `..` (important, new)

`Allowance.wild_covers?/2` (`allowance.ex:84`) lets a `*` segment match
`..`, `.`, `%2e%2e` or an empty segment, and request targets keep dot
segments as sent (`describe.ex:389`, `request_head.ex:64`). You allow
similar, any id, on `DELETE api.github.com/repos/o/r/hooks/123`; the
agent sends `DELETE /repos/o/r/hooks/..`, which goes with GitHub's real
value, unasked. On a server that normalises dot segments, that is
`DELETE /repos/o/r`. Probes: `network/policy_probe.exs` (G7) and
`network/fixed_call_pipeline_probe.exs` ("an allowance for DELETE of a
webhook by id…"). **Fix:** refuse dot and empty segments in request
targets that carry a placeholder, or never let `*` cover them.

### 3. An answer can bring a real value into the VM (important, older)

`Http1.echo/2` (`driver/http1.ex:744`) looks only for the values MWT put
into that request. Stripe's key in the answer to a request carrying
GitHub's placeholder, or GitHub's real value in an answer to a request
that carried none, reaches the VM, and the firewall isn't told. It takes
a service that hands back a secret it holds (config vars, a secret
manager, a file in a repository). Point 13 and "What MWT sees" in the
model say every answer MWT reads is cut when one of your values comes
back. Probes: `network/answer_scan_probe.exs`. **Fix:** scan every
answer MWT reads for all your values (`Values.secrets`), cut, tell the
firewall; or say in the model that only echoes are cut.

### 4. The grade reads narrower than it is (important, new)

- Any value with a `pattern` is *Narrow*, whatever the pattern allows
  (`openness.ex:172`, `param.ex:252`): `kubectl $P` with
  `^[a-z0-9 ./-]+$` ("delete pods --all" passes), `gh api "$P"` with
  `^.+$`.
- Graded *Wide* but open: `echo "$P" | sh`, `bash <<< "$P"`, `bash -lc`
  and `sh -ec` (bundled flags, line 123), `timeout 60 bash -c`,
  `sudo "$P"`, `xargs` (dropped as a wrapper, `host_command.ex:372`, yet
  the model lists it), `"$P/deploy.sh"`, `{ eval "$P"; }`, `awk`,
  `perl -E`, `python3 -Ic`, `node -p`, `docker run IMG "$P"`.
- Q8 holds: the grade never changes what asks.
- Probes: `commands/openness_grade_probe.exs`.
- **Fix:** grade a pattern by what it can match (a fixed list, or no
  spaces, `-` or `/` at the start); skip every wrapper; look for pipes
  into shells and bundled `-c`. And see decision B below.

### 5. A real value as a parameter's *name* isn't scanned (important, new)

`mwt call ID ghp_…=x` is refused as an unknown parameter, and the full
value goes into the activity log and back to the agent; the firewall
isn't told. `texts/1` (`server.ex:436`) scans a map's values only;
proposals' `--set` and `--fill` keys likewise. Probe:
`commands/saved_command_values_probe.exs`, "a real value sent as a
parameter's name is not looked at". **Fix:** scan keys too.

### 6. Refused asks leave no line in the activity log (important, new)

A command refused because host commands are locked or its saved command
is off, and a fixed call refused for a lock or a blocked host, leave no
line: only refused *values* are logged (`server.ex:1312`, `:2443`). The
audit's promise is every action, refused ones included. Probes:
`commands/saved_command_values_probe.exs` ("audit: …") and
`network/fixed_call_pipeline_probe.exs` ("a fixed call refused before it
is built leaves a line"). **Fix:** log every refusal on these paths with
`Decision.refused/1`.

### 7. Withdrawn: a fixed call picking its network by name

First reported as a fixed call refused (`grant_off`) where the agent's
own request to the same public host would go out, when an off grant over
another network lists that host. It holds after all: MWT's DNS refuses a
name only off grants list (`Gate.lookup/2`), so the agent's own request
never reaches the Internet's grant either. The probe had skipped DNS.

### 8. A fixed call's card doesn't name the network grant that asks (minor, new)

With a call on *Auto* and its host's network grant asking, the card says
only "Grant: pr view": `call_request` drops `about.asking`
(`host_runs.ex:89`, `:436`). "One decision, one card" names every grant
that asks. A card for a call also takes no allowance, so a network grant
that asks makes every call to its host ask. Probe:
`network/fixed_call_pipeline_probe.exs`.

### 9. Smaller gaps

- A placeholder percent-encoded in a path or form body goes to an
  unlisted host (`policy.ex:272`, literal match only).
- A credential that only fixed calls are over is unknown to `Policy`
  (`policy.ex:256`), so its placeholder isn't checked for where it goes.
  No value leaks.
- The value floor splits on `/` only: `..\..\admin` passes
  (`param.ex:398`).
- `PYTHONPATH`, `NODE_OPTIONS`, `PERL5OPT`, `KUBECONFIG`, `HTTPS_PROXY`
  are accepted as parameter names (`param.ex:65`): every program the
  script starts reads them.
- `FixedCall` records what this machine's resolver answered as MWT's DNS
  answer for 60 s, for any host (`fixed_call.ex:106`): a host a VPN grant
  with its own resolver names could later be reached at that address
  (read, not probed).
- Base64 of a value in command output isn't seen (by design of the scan).

### 10. What humans and agents read contradicted the model (fixed in this pass)

- Agents were told Commands agents write "needs no grant: you may always
  ask" (`mwt help`, the refusal of `mwt run`, the card's help); the code
  refuses while it is off.
- *Action* meant a fixed call for agents, anything leaving the VM in the
  model, with seven names for fixed calls across texts.
- `mwt why URL`'s help said "the strictest wins"; the code and its own
  output say the most permissive grant counts.
- The saved command's *With credentials* hint asked for *Allow your
  machine*, which is gone.
- The kind picker said *Runs on VM* and *Runs on host* (Q6 removed them,
  and a fixed request doesn't run on your machine), "the kind decides
  where it runs" (point 7 says it doesn't), and that a fixed call is "safe
  to let through without asking" (point 8 says only if its template is
  narrow).
- *your machine* named the Host commands resource in the page header,
  the guides, `mwt why` and refusals (`mwt propose machine`).
- The start setting read *Enabled, ask* beside *On* everywhere else.
- `mwt grants` printed "MWT's tools over MWT's tools" seven times, and
  never showed a fixed call's grade, which Q8 says it does.

## Decisions for you

- **A. Pin at accept, and old saved commands ask once.** The fix to
  finding 1 makes each saved command made before this release ask on its
  next run, showing what it runs. The alternative, pinning them silently
  at upgrade, pins whatever is there now, unseen.
- **B. Q8 and Q3 pull against each other.** Q3 says a command the agent
  writes always asks; Q8 lets a fixed call graded *Open* (open use in
  disguise, `kubectl $ARGS`) run on *Auto*, an agent's proposal included.
  With the grade as it is (finding 4), *Narrow* can't be trusted either.
  Options: keep Q8 and fix the grader; or refuse *Auto* for a host
  command graded *Open*, which holds Q3 at the cost of one more rule.
- **C. A saved command's exception** ("Where today's code still
  differs") is still open: it needs only itself, not Commands agents
  write.
- **D. Scan every answer** (finding 3) costs a pass over each body MWT
  reads; saying in the model that only echoes are cut costs a guarantee.

## Changed in this pass

- **What agents read** (`priv/sandbox/agents.md`, the guides, `mwt` help
  and refusals, `mwt grants`, `mwt why`): *fixed call*, a *fixed request*
  or a *saved command*, in place of *action*; *Host commands* in place of
  *the user's machine*; Commands agents write needs its grant on; the
  overlap rule as the code has it; credential in place of token; the
  refusal codes agents can meet; `mwt grants` lines say each grant's kind
  and resource once, and each fixed call's grade unless *Narrow*.
- **The Grants pages:** the page header, the kind panel and the kind
  picker, *What the VM gets*, the start setting (*On, ask*, *On, auto*),
  field hints that repeated their `?` and the resource pages now say one
  specific thing each, or nothing where a control already says it. A
  command an agent wrote reads *Written by the agent* on its card, a saved
  one *Saved command*.
- **For humans:** [grants.md](../grants.md), how grants work today, for
  setting them up; the README's sandbox section and
  [agent_sandbox.md](../agent_sandbox.md)'s current-tense text follow the
  model.
